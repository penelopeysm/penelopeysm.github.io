Submodels

Wren allows models to be nested within other models. This is useful for building complex models from simpler components, and for reusing models in different contexts.

Basic example

Suppose that we have the following inner model, which we'll embed inside an outer model:

using Wren, Distributions@model function inner()    x ~ Normal()endrand(inner())
VarNamedTuple
└─ x => 0.4928602021081369

When we write x ~ Normal(), what happens is that the result of rand(Normal()) (i.e., a float) is stored in the parameter x.

Likewise, when we write a ~ inner(), the result of rand(inner()) (a VarNamedTuple) is stored in the parameter a.

We could equivalently say that all the variables inside inner are prefixed with a, but thinking of it in terms of rand() is more precise.

@model function outer()    a ~ inner()endvnt = rand(outer())
VarNamedTuple
└─ a => VarNamedTuple
        └─ x => -0.6501318307692303

We can access the inner model by indexing into this:

vnt[@vn(a.x)]
-0.6501318307692303

Accessing return values

With a distribution on the right-hand side of ~, rand(dist) is indeed the only output that we are interested in. However, with a submodel, we may also be interested in the return value of the submodel, which is not part of the latent variables.

In order to allow users to access the return value, Wren stipulates that the prefix ~ submodel expression evaluates to the return value of the submodel. Thus, you can write retval = (prefix ~ submodel):

Note

The parentheses are not strictly required because ~ has higher precedence than =, but it's clearer to include them.

@model function inner_with_retval()    x ~ Normal()    return x^2end@model function outer_with_retval()    xsq = (a ~ inner_with_retval())    @observe xsq ~ Normal()endaccs = rand_with_logp(outer_with_retval())
AccumulatorTuple with 3 accumulators
├─ Params => Wren.VNTAccumulator{:Params, Wren.GetParams, VarNamedTuple{(:a,), Tuple{VarNamedTuple{(:x,), Tuple{Float64}}}}}(Wren.GetParams(), VarNamedTuple(a = VarNamedTuple(x = -0.20765527997175146,),))
├─ LogPrior => Wren.LogPriorAccumulator(-0.940498890854746)
└─ LogLikelihood => Wren.LogLikelihoodAccumulator(-0.9198682312486709)

The value of xsq should be the latent a.x squared, so we can check that the likelihood matches:

xsq = params(accs)[@vn(a.x)]^2logdensityof(Normal(), xsq) ≈ loglikelihood(accs)
true

(You can also use this syntax for distributions, but it's much less interesting as the retval will also be the same as rand(dist).)
