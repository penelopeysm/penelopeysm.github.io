Benchmarking

@bmodel

The easiest way to benchmark models is to use the @bmodel macro:

using Wren, Wren.Dists@wren function f()    x ~ Exponential()    z ~ MvNormalScale(zeros(3), abs(x) * I)end@bmodel f()
ModelRunResult
  ├ model       : f
  ├ backend     : nothing
  ├ n_params    : 4
  ├ rand        : 92.134 ns (11 allocs: 672 bytes)
  ├ logjoint    : 23.534 ns (4 allocs: 160 bytes)
  └ lp          : 28.772 ns (4 allocs: 160 bytes)

When passed a single argument, @bmodel will benchmark:

  • rand: the time it takes to sample a set of parameters from the model
  • logjoint: the time it takes to compute the log joint probability of a set of parameters
  • lp: the time it takes to compute the log-joint probability, but with a vectorised interface (this is the same as e.g. LogDensityProblems.logdensity, if you are familiar with that interface).

Note that all of these are median benchmarks.

To access the data in this benchmark, you can directly access the fields of the ModelRunResult object. The relevant fields are named {function_name}_bench:

br = @bmodel f()br.lp_bench # This is a `Chairmarks.Sample`
28.674 ns (4 allocs: 160 bytes)
br.lp_bench.time, br.lp_bench.allocs
(2.8673509286412513e-8, 4.0)

AD

To additionally benchmark gradients, you can pass an AbstractADType as the second argument to @bmodel:

using Enzyme# `Wren.DEFAULT_AD` is the same as `AutoEnzyme(; mode=Reverse)`.@bmodel f() DEFAULT_AD
ModelRunResult
  ├ model       : f
  ├ backend     : AutoEnzyme(mode=EnzymeCore.ReverseMode{false, false, false, EnzymeCore.FFIABI, false, false}())
  ├ n_params    : 4
  ├ rand        : 87.766 ns (11 allocs: 672 bytes)
  ├ logjoint    : 23.281 ns (4 allocs: 160 bytes)
  ├ lp          : 29.255 ns (4 allocs: 160 bytes)
  ├ lp_and_grad : 95.902 ns (10 allocs: 416 bytes)
  └ grad / lp   : 3.278

In addition to the three columns above, this will also benchmark lp_and_grad, which is the time taken to compute the log-joint plus its gradient (i.e., LogDensityProblems.logdensity_and_gradient).

More control

If this isn't enough and you want to customise exactly what gets benchmarked, and to test correctness, Wren also provides a function benchmark_and_test which has a staggering number of options. (There are also slightly simpler versions, benchmark_ad, and test_ad.)
