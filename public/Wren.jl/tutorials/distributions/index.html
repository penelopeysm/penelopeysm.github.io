Distributions

A probabilistic programming language is nothing without its distributions!

Wren has a fully generic interface which allows you to plug in any object that provides:

  • Base.rand(rng, dist)
  • DensityInterface.logdensityof(dist, sample)

However, not all distribution providers are created equal. This page will cover a couple of choices.

Built-in distributions

Wren ships with its own set of distributions, which is currently very small. (Help with expanding this set is very welcome!) You can see a full list of the built-in distributions on this page.

To access these, you need to add using Wren.Dists to your code. (The reason Wren doesn't automatically re-export them is to avoid name clashes if you want to load e.g. Distributions.jl.)

In the first instance we very much recommend trying these first. Their constructors are designed to be as close as possible to the equivalent constructors in Distributions.jl. The reason for this is because Wren's built-in distributions are intended to:

  • Work with Wren's @batch macro in a meaningful way (i.e., Wren provides vectorised equivalents of them);

  • Be compatible with Reactant (many Distributions.jl objects use scalar indexing and have type bounds on e.g. <:Real, which makes them incompatible); and

  • Minimise code paths that can potentially cause errors with Enzyme.

Role in ecosystem

Wren's own distributions are not intended to be a fully-fledged replacement for e.g. Distributions.jl. For example, a huge swathe of Distributions' API is simply unimplemented.

In many ways, Wren's distributions are meant to be a proof-of-concept that such a system can be used for Wren's PPL aims. We would be very happy if there was a centralised effort to develop GPU-friendly distributions that could be used across multiple PPLs, including Wren.

Distributions.jl

You can also use any distribution from Distributions.jl as they already obey the interface above.

This is useful if you just want a familiar interface and don't need any of the features of Wren's built-in distributions. Indeed, Wren promises that @batch will still work correctly with these distributions; it's just that it will fall back to using product_distribution, which won't give you any speedups over the unbatched loop.
